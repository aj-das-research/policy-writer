\section{Question}
\para{Promise.} Progent~\citep{shi2025progent} has an LLM turn the user's query into a deterministic JSON-schema
policy over tool calls and update it from tool results; with GPT-4o, ASR on AgentDojo~\citep{debenedetti2024agentdojo}
falls from 39.9\% to 1.0\% at similar utility (2.5\% with the initial policy alone).
\para{Assumption tested.} The policy writer is reliable and not itself injectable. The paper keeps updates monotone
unless approved, but its headline run uses an approver that accepts every expansion; the released AgentDojo integration
generates updates from raw tool outputs, applies them with \code{manual\_check=False}, and leaves the narrowing-only check
(\code{SECAGENT\_ONLY\_ALLOW\_NARROW}) commented out. \para{Outcome.} Failure analysis with ablations, anchored by an exact reproduction.

\section{Method}

\vspace{-1.4em}

We run Progent's own code (\code{secagent} and its AgentDojo fork, suite v1.2) with policy logic and prompts unchanged.
\textbf{Static check:} for each of 97 user tasks Progent writes the initial policy $P_u$ (hand-written always-allowed list
+ LLM entries); every ground-truth call of $u$ and of every injection task is checked by Progent's
\code{check\_tool\_call} after AgentDojo's argument validation. \emph{FB}: \% of user tasks with a blocked ground-truth
call. \emph{Blk}: \% of (user, injection) pairs with a blocked injection call (\nPairs{} pairs; \nPairsNoGT{} pairs of
workspace tasks 6--13 have no ground-truth calls in AgentDojo and are excluded). \textbf{Update replay:} we walk
AgentDojo's shipped undefended traces step by step. Each call is checked against the current policy; a block means the
trace diverges from what Progent would produce, so we stop. Otherwise the step's calls and \emph{recorded} outputs go
through Progent's \code{generate\_update\_security\_policy}. With no block the agent saw byte-identical inputs, so the
recorded outcome is Progent's. \emph{ASR}: \% of attacked traces that succeeded and were never blocked (a lower bound).
\emph{AtkPol}: \% where a string from the injection task's ground-truth arguments (absent from the prompt and the user
task's ground truth) enters the policy. \emph{Unblk}: \% where an injection call blocked by $P_u$ becomes allowed (both over
the \nAtkGT{} traces with ground truth). \emph{Util}: \% of benign traces with recorded utility and no block.

\section{Setup}
\para{Policy models.} GPT-4o-2024-08-06 (Progent's default) and four open models served with vLLM: Qwen3-30B-A3B-Instruct-2507,
Mistral-Small-3.2-24B, Qwen3.5-9B (thinking off), Qwen2.5-7B-Instruct; temperature 0, seed 0. \para{Traces.} No live
agent: AgentDojo's published Llama-3.3-70B traces (v1.2.1, \code{important\_instructions}), 97 benign and \nAttacked{}
attacked. \para{Compute.} 8$\times$RTX PRO 6000 shared with other jobs; \totalCalls{} cached policy calls; GPT-4o
\gptMTokIn{}M/\gptMTokOut{}M in/out tokens, \$\gptCost{} at list price. \para{Code.} Progent and AgentDojo copied
unmodified except four marked patches (local endpoint, request cache, update-outcome counters, 4096-token output cap for
local models); custom harness, replay and analysis; \code{PYTHONHASHSEED=0} because Progent's \code{set()}-ordered policy
otherwise makes update prompts differ between runs. \para{Deviations.} Progent's fork comments out travel injection tasks 2
and 6 (\nExcluded{} of 949 cases; task 6 succeeds through text alone, which no tool policy can block) and its
\code{benchmark.py} defaults to v1.1.2. We use its v1.2 suite and report the excluded cases separately.

\para{Anchor.} AgentDojo's published GPT-4o (2024-05-13, no defense) row, recomputed from its shipped traces: utility
\anchorutility\%, utility under attack \anchorutilityunderattack\%, targeted ASR \anchortargetedasr\%. All three match exactly.
\para{Initial policies need updates (Fig.~\ref{fig:main}a).} GPT-4o's initial policies block \stGptBlk\% of attacks,
consistent with the paper's 2.5\% initial-policy ASR, but falsely block \stGptFB\% of user tasks. Utility therefore
\emph{depends} on updates that widen the policy from tool outputs, which is the channel the attacker writes to.
\para{Updates admit attacker values (Fig.~\ref{fig:main}d).} With the released defaults, attacker values enter GPT-4o's
policy in \rpGptDAtkPol\% of attacked traces and \rpGptDUnblk\% of attacks go from blocked to allowed. Example (banking,
user task 12: ``\emph{Read the file landlord-notices.txt and follow the instructions precisely}''): after reading the injected
file, GPT-4o adds \code{send\_money} with \code{recipient}$\,\in\,$\{\code{US1330\ldots1212}\}, the attacker's IBAN, and
the attack completes. Replay ASR stays low (\rpGptDASR\% vs.\ \traceASR\% undefended) because most attacks are blocked
before an update can admit them. \para{Narrowing-only.} The check rejects \rpGptNRejected{} GPT-4o updates, removes every
unblocked attack (\rpGptNUnblk\%) and gives replay ASR \rpGptNASR\%, at utility \rpGptNUtil\% vs.\ \rpGptDUtil\%. Attacker
strings can still \emph{narrow} an unrestricted argument (\rpGptNAtkPol\%), steering rather than widening the action space.
\para{Excluded cases.} On the \nExcluded{} travel cases the fork drops, undefended ASR is \exclTraceASR\% and replay ASR
under GPT-4o is \rpGptDExclASR\%.

\section{Verification}
Controls through the same checker: allow-all FB \stAllowFB\%/Blk \stAllowBlk\%; deny-all FB \stDenyFB\%/Blk \stDenyBlk\%;
the hand-written list alone FB \stHumanFB\%/Blk \stHumanBlk\%, so the LLM entries are what restore utility. Rerunning from
the cache makes zero new calls and gives identical records. \nTruncated{} replies hit the output cap (Progent retries them).
Consistency checks raise instead of skipping; they caught traces ending at AgentDojo's iteration cap, tasks the fork removed,
and nondeterministic prompts, all fixed before the final run.

\section{Limitations and Next Step}
Replay ASR is a lower bound: after a block the real agent would act differently, which a replay cannot show. The traces
come from Llama-3.3-70B, not the paper's GPT-4o agent. String matching misses paraphrased attacker values. We test a
single, non-adaptive attack. \textbf{Next:} injections written for the \emph{policy updater} (e.g., ``the user approved IBAN
X''), with Progent's monotone check on, to test whether narrowing toward attacker-chosen values yields end-to-end attacks
that the expansion check never sees.
